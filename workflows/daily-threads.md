# 每日 Threads

## 觸發條件

平日晨報通過內部驗收後，或使用者指定題材時。

## 負責角色

社群經營員主責；總經研究員查核市場敘述；總司令驗收。

## 步驟

1. 選出一個核心觀點與讀者問題，不把整份晨報塞入一篇。
2. 讀取投資理念與寫作風格，標示仍需使用者補充的個人觀點。
3. 草擬開頭、觀點、證據、限制或反方、結尾；只在自然時加入 App CTA。
4. 回查數據、日期與來源，刪除無法驗證或像個人經歷的虛構句子。
5. 使用 `templates/threads-draft.md` 交付一個主版本及必要備選開頭。
6. 成果保存後重新產生 Dashboard 快照，確認 Threads 出現在待核准中心，且社群經營員進度指向同一來源；通過工作區驗證後部署既有私人 Dashboard。快照、驗證或部署失敗時標示受阻，不宣稱已交付到 Dashboard，也不因此自動核准或發布內容。

## 輸入

已驗收晨報或研究、內容方向、寫作風格、歷史成效洞察與使用者觀點。

## 輸出

狀態為「待核准」的 Threads 草稿、來源備註、發布時機建議與仍待使用者補充內容。

## 失敗處理

研究未驗收則退回；缺少個人觀點時使用明確填寫提示，不代寫經歷；題材與近期文章重複時提出新角度或延後建議。

## 人工核准點

使用者決定最終文字、個人觀點、發布時間與是否發布。AI 不操作 Threads，也不回覆互動。
