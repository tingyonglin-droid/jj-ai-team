# Dashboard Threads 完整草稿展開設計

## 目標

讓使用者在私人 Dashboard 的 Threads 待核准卡片內閱讀完整草稿，不必離開核准情境。卡片預設收合以維持總覽可掃讀性，使用者點選「查看完整草稿」後在原地展開，並可於同一卡片完成既有兩段式核准。

## 範圍

- 今日總覽與待核准中心共用相同的 Threads 完整草稿元件與互動。
- 完整草稿包含來源 Markdown 中的所有正文段落與章節，包括主版本、備選開頭、查核與語氣及核准聲明。
- 非 Threads 成果維持現有呈現方式。
- 本次不新增獨立 Threads 頁面、不修改核准語意、不發布內容，也不修改或部署 `jj-invest-public`。

## 資料設計

Dashboard 快照產生器在驗證 Threads 成果後，將 Markdown 解析為既有安全結構化內容模型可表達的標題、段落與清單節點，並把節點附加到對應的 Threads 待核准項目。正式執行時只讀已產生的快照，不依賴 Worker 執行環境的本機檔案系統。

解析內容以完整來源文件為準，不以摘要代替全文。原始 Markdown 不作為可直接注入 HTML 的字串；連結僅接受安全的 HTTP(S) 目的地。若格式無法解析或完整內容缺失，該卡片顯示明確的「完整草稿無法載入」訊息、來源位置與下一步，不把摘要標示為完整草稿。

## 介面與互動

Threads 待核准卡片在既有摘要與來源資訊後新增原生可操作的「查看完整草稿」控制項。預設狀態為收合，展開後控制項文字改為「收合草稿」，完整內容顯示在同一卡片內。展開與收合不改變核准狀態，也不觸發 API 寫入。

既有狀態徽章與兩段式核准按鈕保留在卡片中。使用者展開閱讀後可直接核准；核准仍只代表內部文案通過，不代表已發布 Threads、回覆互動或採取投資行動。

控制項需可由鍵盤操作，並對輔助科技揭露展開狀態及其控制的內容區塊。長草稿沿用 Dashboard 既有字級、行距、清單與卡片寬度，避免建立新的全頁導覽。

## 元件邊界與資料流

1. 快照產生器讀取並驗證 Threads Markdown。
2. 純解析函式把完整文件轉為可安全渲染的結構化區塊。
3. `DashboardSnapshot` 的 Threads 核准項目攜帶完整內容；其他成果不需該欄位。
4. 共用 Threads 草稿元件負責收合狀態與內容渲染，不負責核准寫入。
5. 既有 `ApprovalAction` 繼續單獨處理兩段式核准，避免把閱讀狀態與核准狀態耦合。

## 錯誤處理

- 來源缺失或格式不合契約時，快照驗證保留可追溯 blocker，且不生成看似完整的正文。
- UI 收到缺少完整內容的 Threads 待核准項目時，顯示錯誤、來源與重新產生 Dashboard 快照的下一步；核准按鈕不因摘要存在而冒充已完成全文審閱。
- 展開控制不發送網路請求，因此沒有部分載入或遠端讀取失敗狀態。

## 測試與驗收

- 產生器測試確認 Threads 待核准項目包含來源文件的所有章節與代表性正文，且內容順序不變。
- 型別與解析器測試確認結構化區塊安全、可重現，非 HTTP(S) 連結不可點擊。
- 元件測試確認 Threads 草稿預設收合、可展開與收合，完整正文可讀，並具備正確的無障礙狀態。
- 路由測試確認今日總覽與待核准中心皆使用同一完整草稿體驗，非 Threads 卡片不出現該控制項。
- 既有兩段式 Threads 核准測試持續通過，證明閱讀功能不改變核准事件契約。
- 正式 build、渲染成品測試與 `sh scripts/validation/validate-workspace.sh` 全部通過。
- 部署至既有 owner-only 私人 Sites 專案後，未授權請求仍被拒絕；授權使用者可在卡片內展開完整草稿並核准。

## 人工核准與安全邊界

- 本規格的核准只授權 Dashboard 閱讀功能實作與既有私人 Dashboard 更新。
- Threads 成果仍需使用者逐版本核准；核准後也不會自動發布。
- 不改變 Dashboard 允許名單、Sites 公開狀態、D1 綁定或外部系統權限。
- 不在快照、提交或回覆中加入憑證、私人帳號識別資訊或其他祕密。
