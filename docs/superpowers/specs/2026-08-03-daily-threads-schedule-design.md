# 每日 Threads 條件式排程設計

## 目標

在每個有新完成美股交易時段的台灣平日，於當日晨報與市場風險報告通過內部驗證後，立即觸發社群經營員產生一篇 Threads 待核准草稿，更新私人 Dashboard，並通知使用者審閱。排程只自動產生與交付內部草稿，不自動核准或發布。

## 觸發與交易日規則

- 觸發來源是晨報流程的成功交付事件，不另設固定 08:00 或 12:00 排程。
- 晨報成功交付須代表：存在當日應有報告、恰好五則事件、研究與來源契約通過、對應市場風險報告已產生，且工作區驗證成功。
- 只有 `DashboardSnapshot.expectation` 判定當日應建立新晨報，且該晨報涵蓋新的已完成美股交易時段時才執行。
- 台灣週末、美股完整休市日、交付門檻前沿用舊報，以及沒有新完成交易時段時跳過，不把舊晨報重新包裝成今日 Threads。
- 晨報延遲時等待晨報成功；若晨報最終受阻，Threads 任務同步標示受阻而不產生草稿。

## 輸入與內容流程

社群經營員讀取當日最新版且通過內部驗證的晨報、對應市場風險報告、投資理念、寫作風格及可用的近期 Threads 成效。內容流程沿用 `workflows/daily-threads.md`：選擇單一核心觀點與讀者問題，回查數據、日期、來源、限制與反方證據，產生一個主版本及必要備選開頭。

如果草稿需要使用者的真實個人判斷，必須明確標示待補充，不得虛構第一人稱經歷、持股、操作或觀點。研究不足、來源衝突或無法形成與近期文章有區隔的核心觀點時，不強行湊稿。

## 輸出與狀態

- 草稿保存至 `records/content/threads/`，檔名包含報告日期、主題識別與兩位數版本。
- 草稿使用 `templates/threads-draft.md`，狀態固定為 `待核准`，並記錄來源晨報及發布前需重新確認的事件。
- 同一晨報成果版本最多產生一個對應 Threads 成果版本；晨報內容雜湊或版本改變後，才允許建立 Threads 新版本。
- 不覆寫既有 Threads 成果。需修訂時追加新版本，保留原始草稿與核准紀錄。

## 防重複與可追溯性

以「晨報來源路徑＋晨報版本＋內容雜湊」作為觸發身分。流程開始前查找已保存的 Threads 紀錄；若已有相同觸發身分，回報 `skipped` 並指向既有成果，不重複生成、部署或通知。

Threads 草稿需保存來源晨報路徑、資料代表時間與必要依賴。Dashboard 的待核准項目、社群經營員目前任務及完整草稿必須指向同一來源成果。

## Dashboard 交付

草稿保存後依序：

1. 重新產生 Dashboard 快照。
2. 驗證 Threads 出現在待核准中心，完整草稿可展開，社群經營員進度為等待人工核准。
3. 執行 Dashboard 完整測試、正式建置與 `sh scripts/validation/validate-workspace.sh`。
4. 部署既有 owner-only 私人 Sites 專案，不建立新 Site、不改變允許名單。
5. 回報成功、跳過、有限版或受阻狀態，以及草稿來源與 Dashboard 位置。

任一步驟失敗時不得宣稱已交付；若草稿已保存但 Dashboard 部署失敗，保留草稿並把任務標示受阻，供下一次安全重試。

## 排程形態

以既有每日晨報 automation 的成功結果串接 Threads 子流程；不建立與晨報競速的獨立固定時間任務。automation prompt 必須讀取專案 `AGENTS.md`、晨報、風險與每日 Threads 工作流，先確認交易日及晨報驗證結果，再決定執行、跳過或受阻。

若現有 automation 平台不支援同一任務內條件式後續步驟，才建立第二個 automation；第二個 automation 也必須以已驗證的新晨報觸發身分作為必要前置條件，而非僅依時間啟動。

## 失敗處理

- 晨報或風險報告缺失／驗證失敗：Threads 狀態為受阻，不產生草稿。
- 合格來源不足或衝突：停止確定性敘述，列出缺口，不以推測補造。
- 同一觸發身分已處理：回報 skipped，不建立新版本。
- 草稿驗證失敗：保留失敗原因，不更新 Dashboard 為可核准。
- Dashboard 測試、建置或私人部署失敗：保留草稿與受阻狀態，後續只重試未完成的安全交付步驟。
- 07:30 後晨報才成功：完成後立即觸發 Threads，不將舊報標為今日成果。

## 人工核准與永久邊界

- 自動化只能產生狀態為 `待核准` 的內部 Threads 草稿。
- 使用者決定最終文字、個人觀點、發布時間與是否發布。
- Dashboard 核准只記錄內部文案核准，不觸發 Threads 發布、留言、私訊或其他互動。
- 不提供個人化買賣、持股調整或投資行動建議。
- 不修改或部署 `jj-invest-public`，不改變私人 Dashboard 存取政策或外部憑證權限。

## 驗收標準

- 使用測試晨報執行一次：產生恰好一份待核准草稿；再次以相同觸發身分執行時跳過。
- 使用真實公開資料的人工驗證晨報執行一次：草稿完整、來源可追溯、反方與缺漏明確，Dashboard 可展開全文。
- 週末、完整休市日、沿用舊報與晨報受阻情境均不產生新草稿。
- 晨報版本或內容雜湊改變時，可產生新的 Threads 版本且不覆寫舊稿。
- Dashboard 測試、正式 build、工作區驗證及 owner-only 部署驗證全部通過。
- automation 啟用後，下一次執行時間與條件式觸發規則可查，且未授權任何自動發布或投資行動。
