# Dashboard 已核准 Threads 歷史閱讀設計

- 狀態：已核准設計；尚未授權實作或上線
- 文件日期與版本：2026-08-03、v01
- 負責人：App 設計員
- 核准人：使用者

## 問題與證據

- 目標使用者：私人 JJ AI Team Dashboard 的授權使用者。
- 使用情境：使用者需要回看過去已核准的 Threads 草稿全文，但現有 Dashboard 只在今日總覽與待核准中心呈現尚待決定的 Threads 成果。
- 問題證據：使用者於 2026-08-03 明確要求在 Dashboard 查看已核准的歷史 Threads 草稿，並確認首要用途是「回看已核准全文」。目前沒有使用頻率、歷史筆數或產品分析數據。
- 為何現在：Dashboard 已具備 Threads 待核准全文閱讀與晨報歷史閱讀模式，可沿用現有安全內容模型與導覽慣例，補足核准後的閱讀斷點。

## 用戶故事與價值

> 身為私人 Dashboard 的授權使用者，我希望從內容區瀏覽已核准 Threads 草稿並開啟單篇全文，以便回看當時通過的完整文案及其版本與核准脈絡。

- 免費版價值：不適用；此功能屬 owner-only 私人工作 Dashboard。
- 付費版增量：不適用，本次不設計商業化分級。

## 方案比較與決策

### 放置位置

1. 在待核准中心增加「已核准歷史」：改動較小且接近核准紀錄，但會把已完成與待決定工作混在同一工作區。
2. 新增「內容」入口並建立 Threads 歷史：讓待核准中心維持行動導向，歷史草稿成為可閱讀、可追溯的內容資產。

決策採用方案 2。主選單在「晨報全文」之後、「AI 員工」之前新增「內容」。第一版內容區只包含 Threads 歷史，不預先建立 IG、題庫或成效頁。

### 全文閱讀方式

1. 歷史列表加獨立全文頁：長文最好讀，可直接定位單篇，版本與來源脈絡清楚。
2. 歷史列表內展開全文：少一次換頁，但多篇展開後難以掃讀，也沒有穩定的單篇網址。
3. 直接顯示最新全文並以前後篇切換：初始閱讀最快，但找舊內容與理解歷史全貌較慢。

決策採用方案 1，並沿用既有晨報「歷史列表 → 獨立全文頁」的使用心智。

## 範圍與非目標

### 包含

- 新增受保護的「內容」入口。
- 新增只列出已核准 Threads 成果的歷史列表，依核准成果日期由新到舊排列。
- 每張歷史卡片顯示日期、標題、核准版本、核准時間與「閱讀全文」入口。
- 新增每個已核准 Threads 版本的獨立全文頁與穩定路徑。
- 全文頁顯示來源 Threads Markdown 中的標題、正文、備選開頭、查核與語氣說明、來源、版本及核准時間。
- 同一天若有多個版本各自獲核准，分開保留並可分別開啟，不覆寫先前版本。

### 非目標

- 不在第一版新增搜尋、標籤、題材重用、成效串接、IG、編輯、刪除或發布功能。
- 不把已核准歷史放回待核准中心；待核准中心繼續只顯示尚待決定的成果。
- 不把「已核准」表示為「已發布」，也不自動發布、回覆或進行任何投資操作。
- 不修改核准語意、Dashboard 允許名單、Sites 公開狀態、外部專案或 `jj-invest-public`。
- 與既有 Beta 系統無連動。

## 畫面流程與狀態

1. 使用者從主選單進入「內容」。
2. 內容首頁顯示 Threads 歷史列表；第一版沒有其他內容類型分頁。
3. 使用者選擇一張已核准成果卡並點選「閱讀全文」。
4. 獨立全文頁呈現該核准版本的完整結構化內容、核准資訊與來源定位。
5. 使用者可返回 Threads 歷史列表繼續選擇其他成果。

- 載入狀態：沿用受保護 Dashboard 的伺服器端載入行為，不以未驗證摘要先行冒充全文。
- 空值：沒有已核准成果時顯示「目前沒有已核准 Threads 草稿」，不拿待核准內容補位。
- 資料不足：核准事件存在但無法取得對應全文時，歷史項目顯示不可閱讀狀態、來源定位、原因與修復下一步。
- 過期／錯誤：成果版本、雜湊或來源不吻合時不得顯示正文；無效或不安全連結不可點擊。
- 核准資訊：顯示核准版本與核准時間；若核准事件尚未同步回工作區，標示「已核准、尚未同步」。
- 行動邊界：全文頁沒有核准、編輯、發布或刪除控制項。

## 資料設計與資料流

1. Dashboard 快照產生器掃描有效的 Threads Markdown 成果，保留每個版本不可變的來源、版本、內容雜湊與完整結構化內容。
2. 既有安全 Markdown 解析流程把標題、段落、清單與表格轉成可渲染區塊；原始 Markdown 不直接注入 HTML。
3. 正式請求依既有順序完成授權、載入快照、載入核准事件，再以成果 ID、版本及內容雜湊套用核准狀態。
4. 歷史列表只接收成功匹配核准事件的 Threads 版本；未核准、已退回或匹配失敗的版本不進入正常歷史列表。
5. 全文頁只讀同一份已驗證快照內容，不在 Worker 執行期間讀取工作區檔案。

| 欄位／事件 | 定義 | 來源 | 新鮮度／限制 |
|---|---|---|---|
| `artifact_id` | 不隨標題改變的 Threads 成果識別碼 | Threads 成果與 Dashboard 快照 | 必須與核准事件一致 |
| `record_date` | 成果代表日期 | Threads Markdown | ISO 日期；不可由核准時間推測 |
| `title` | 歷史列表與全文頁標題 | Threads Markdown | 缺失時視為格式錯誤，不虛構 |
| `version` | 被核准的成果版本 | 檔名／成果欄位與核准事件 | 必須完全一致 |
| `artifact_hash` | 被核准內容的不可變比對值 | 快照產生器與核准事件 | 不符時 fail closed |
| `approved_at` | 使用者完成核准的時間 | Dashboard 核准事件 | 保留時區；不得以檔案更新時間代替 |
| `approval_sync_status` | 核准事件是否已同步回工作區 | 核准事件與同步狀態 | 未同步不撤銷 Dashboard 內的有效核准 |
| `blocks` | 可安全渲染的完整草稿內容 | 經驗證 Threads Markdown | 缺失或解析失敗時不得以摘要代替 |
| `source_refs` | 原始成果與核准紀錄定位 | 工作區檔案與核准事件 | 僅對授權使用者呈現 |

## 元件邊界

- Threads 歷史資料組裝器：把已驗證 Threads 版本與核准事件配對，輸出只讀歷史模型，不負責畫面狀態。
- Threads 歷史列表：只負責排序、摘要資訊、空值與錯誤項目，不解析 Markdown。
- Threads 全文頁：只負責單一已核准版本的內容與追溯資訊，不執行核准或發布動作。
- 共用安全內容渲染器：沿用待核准 Threads 與晨報全文的結構化區塊能力，避免建立第二套 Markdown 渲染路徑。
- 既有核准事件層：維持核准判定的唯一依據；歷史頁不得另建可漂移的 `approved` 布林值。

## 成功指標與驗證

- 主要功能驗收：測試資料中的每個有效已核准 Threads 版本都能從歷史列表開啟對應全文，且未核准版本出現數為零。
- 完整性驗收：全文包含來源文件所有代表性章節且順序不變；摘要不得冒充完整內容。
- 追溯驗收：每個歷史項目均可定位成果 ID、版本、雜湊、核准時間與來源。
- 防護指標：匿名請求對內容列表與全文路徑全部被拒絕；沒有任何閱讀操作建立核准、發布、編輯或刪除事件。
- 可用性驗收：桌面與手機皆可完成「內容 → Threads 歷史 → 單篇全文 → 返回列表」流程，長文不產生頁面橫向溢位；必要表格可在自身範圍水平捲動。
- 產品使用指標：目前沒有使用頻率基準或分析授權，本次不虛構數值目標；上線與量測方式須另經使用者決定。

## 測試與錯誤處理

- 產生器測試覆蓋：單一核准版本、同日多個已核准版本、未核准版本、雜湊不符、來源缺失及 Markdown 解析失敗。
- 資料套用測試證明只有成果 ID、版本、雜湊及核准動作皆符合的事件能產生歷史項目。
- 路由測試確認內容列表與每個全文網址皆需 owner-only 授權，且直接開啟有效網址可成功閱讀。
- 元件測試確認排序、空值、不可閱讀錯誤狀態、核准未同步標示與安全連結行為。
- 渲染測試確認全文結構、手機版單欄、長文寬度與表格溢位處理。
- 正式 build、既有核准流程回歸測試及 `sh scripts/validation/validate-workspace.sh` 必須全部通過。

## 風險、依賴與核准

- 風險：現有 Dashboard 快照主要把完整 Threads 內容附在待核准項目；核准後該項目會從待核准陣列移除。緩解方式是建立獨立、不可變的 Threads 版本檔案模型，再由核准事件決定是否進入歷史，而不是從待核准陣列反推。
- 風險：D1 核准事件與工作區同步可能有時間差。緩解方式是以 Dashboard 內有效核准事件維持顯示，另呈現同步狀態，不將兩者混成發布狀態。
- 依賴：現有安全 Markdown 解析器、Dashboard 快照產生器、核准事件儲存與套用流程、owner-only 授權、現有內容渲染器及路由測試架構。
- 待確認：沒有阻擋本設計規格的產品問題；實作前仍需確認現有 Threads 成果的穩定 ID 與版本欄位能涵蓋全部歷史檔案。
- 上線決策：實作、部署、排程與公開狀態都必須由使用者另行核准。本文件不授權修改或部署 Dashboard。
- 核准紀錄：2026-08-03，使用者依序核准「內容 › Threads 歷史」、歷史列表加獨立全文頁、資料與全文內容、異常狀態與驗收設計。
