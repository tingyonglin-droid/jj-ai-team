# Dashboard 核准、交易日狀態與晨報自動化設計

## 目標

修正 Dashboard 以台灣日曆日判斷資料過期的問題，加入可追溯且具防誤觸機制的成果核准操作，補產 2026-07-31 晨報與市場風險指標，並建立每個適用交易日於台灣時間 07:30 前完成的晨報流程。

本設計維持既有研究、核准與發布邊界：自動流程只產生「待核准」成果；核准不等於發布、上線、交易或持股調整。

## 範圍

- 交易日導向的資料新鮮度與警告規則。
- 今日總覽的「資料狀態」及警告／受阻分流。
- 晨報與市場風險指標的逐版本 Dashboard 核准按鍵。
- Dashboard 內的持久化核准事件與版本庫稽核同步。
- 2026-07-31 五則晨報及同日風險指標人工補產。
- 台灣時間週一至週五 06:30 啟動、07:30 前完成的自動流程。
- 私人 Dashboard 測試、部署與主分支整合。

第一版不包含退回原因、留言、批次核准、公開發布、社群發布、個人化投資建議或自動交易。

## 報告日期與交易時段

晨報檔名日期代表台灣早晨的交付日期，不是美國交易日日期。

- 台灣週二至週五晨報，原則上涵蓋前一個美國完整交易時段。
- 台灣週一晨報涵蓋前一個週五美股收盤及其後週末重大事件。
- 美國完整休市日之後不產生例行晨報；提早收盤仍算有效交易時段。
- 2026-07-31 補產版本涵蓋 2026-07-30 美國交易時段。
- 2026-08-03 自動版本涵蓋 2026-07-31 美國交易時段及週末重大事件。

交易日判定由可測試的市場日曆模組負責。正式環境不得依賴即時網路才能判斷新鮮度；專案保存經官方交易所資料核對的年度完整休市日清單，並記錄涵蓋年度、來源與下一次更新日。找不到適用年度時，流程停止做出「最新」結論並顯示設定受阻。

## Dashboard 資料狀態

Dashboard 先由目前時間、台灣時區、交易日曆及 07:30 交付門檻算出「應有報告日期」，再比較最新有效成果。

狀態定義：

- `最新`：目前應有日期的有效成果存在。
- `沿用最近交易日`：週末、休市日或當日 07:30 前尚未到交付門檻，最近一份有效成果仍是預期資料。
- `待更新`：已超過 07:30 且應有的新成果不存在，或晨報與風險指標只完成其中之一。
- `受阻`：日曆設定缺失、文件驗證失敗、研究關鍵資料不足、風險分數不可重現或部署失敗。

舊成果不得改標成今日資料；畫面必須同時顯示實際報告日期、涵蓋的美國交易時段及資料截止時間。

今日總覽將既有「受阻項目」改為「資料狀態」：

- 提醒區顯示 `沿用最近交易日`、`待更新`、有限版及尚待同步等非致命狀態。
- 受阻區只顯示實際阻止研究、評分、建置或部署的錯誤。
- 沒有事項時顯示明確空狀態，不以警告色製造異常感。

## Dashboard 核准體驗

每份狀態為 `待核准` 的晨報與市場風險指標各自顯示核准操作：

1. 使用者點擊「核准」。
2. 同一卡片展開「確認核准此版本」與「取消」。
3. 第二次確認後送出；送出期間停用按鍵並顯示進度。
4. 成功後該版本立即顯示 `已核准`，並移出待核准清單。
5. 失敗時保留待核准狀態、顯示可理解原因，且不得產生半完成畫面。

核准以成果路徑與版本為單位。舊版核准不會核准新版；產生 `v02` 後，`v02` 必須重新核准。第一版不提供「全部核准」。

## 權限與請求驗證

- 所有讀寫均先通過既有 ChatGPT 身分及允許名單檢查。
- 核准 API 只接受同源 POST，拒絕未授權、格式錯誤及超過大小限制的請求。
- 後端不能信任前端傳來的標題或狀態；它必須從當前有效 Dashboard 快照重新取得成果，確認成果存在、版本相符且仍為 `待核准`。
- 操作者只保存穩定的驗證身分識別值，不在核准資料表保存不必要的 Email。
- 重複請求以資料庫唯一約束實現冪等；同一版本只會有一筆有效核准。
- 私人站點的允許名單、公開狀態及環境祕密不得因本功能而放寬。

## 持久化核准紀錄

Sites 的持久化 SQLite／D1 資料庫保存不可覆寫的核准事件，至少包含：

- 事件 ID
- 成果種類
- 成果穩定識別碼、來源路徑與版本
- 核准時的內容雜湊
- 動作（第一版只有 `approve`）
- 操作者穩定識別值
- 核准時間（UTC ISO 8601）
- 版本庫同步狀態與同步時間

資料庫以成果來源、版本及動作建立唯一約束。Dashboard 在授權完成後，將有效核准事件疊加到唯讀內容快照，因此核准後不需重新部署即可立即更新狀態。

資料庫是即時操作紀錄；`records/decisions/` 是專案內的稽核鏡像。同步器只追加決策紀錄或新的已核准版本，不覆寫市場風險歷史，也不把舊版核准套用到新版。

## 版本庫同步與安全界線

每日流程啟動時先處理尚未同步的核准事件：

1. 經獨立服務授權讀取待同步事件。
2. 驗證事件指向的成果版本仍存在且內容雜湊相符。
3. 新增 `records/decisions/` 核准紀錄，並依既有不可覆寫規則建立需要的已核准版本。
4. 通過工作區驗證並提交後，才把事件標為已同步。

同步授權不得使用前端登入憑證、不得把祕密提交到版本庫，也不得為了同步而把 Dashboard 改成公開。若部署平台沒有可安全供本機排程使用的服務授權，第一階段仍可保存並即時顯示 D1 核准，但必須標示「已核准、尚未同步」；不得假裝同步成功。服務授權屬於自動同步的上線前置條件，需在實作驗證時確認，若需要建立或旋轉繞過登入的憑證，必須另取得使用者明確授權。

同步失敗不撤銷已記錄核准；下次執行依事件 ID 重試。內容雜湊不符時停止同步並列為受阻，避免把核准套用到被修改的內容。

## 晨報與風險指標流程

台灣時間週一至週五 06:30 啟動：

1. 檢查是否存在新完成且應納入的美股交易時段；若無，正常跳過並留下原因。
2. 鎖定涵蓋期間，先查原始資料，再用可信二手資料驗證；07:10 鎖定資料截止時間。
3. 建立至少八則候選事件，依發生機率、下跌衝擊、廣度、持續時間及迫近度排序。
4. 固定選出五則最可能影響市場行情、以下行風險為優先的事件。
5. 依既有晨報規格整理數據、傳導鏈、A–D 性質、期限、反方證據、失效條件與後續觀察。
6. 以相同證據產生 0–100 的影子市場風險指標，保留基準分、事件調整、完整度與信心。
7. 產生 `待核准` Markdown，更新 Dashboard 快照，執行測試、建置、工作區驗證及私人部署。
8. 最晚 07:30 回報成功、有限版、跳過或受阻；延遲時不得以舊資料冒充今日成果。

自動流程不得自行核准、發布、調整持股、提供買賣訊號或改變風險方法。

## 2026-07-31 補產

人工補產使用當時可取得且可追溯的資料，固定五則事件並保存：

- `records/daily-briefs/2026-07-31-v01.md`
- `records/market-risk/2026-07-31-v01.md`

兩份成果初始狀態均為 `待核准`。事實須附來源名稱、發布日期、資料期間與連結；資料缺失、來源衝突或無法還原時必須明示，不得以後見之明改寫成當時已知事實。

## 失敗與恢復

- 單一來源失敗：改用其他合格來源並記錄缺口。
- 關鍵資料不足：產生有限版、降低信心；不足以支持總分時不顯示分數。
- 只完成晨報或風險其中之一：保留已驗證成果，Dashboard 顯示 `待更新`，不把整組標成完成。
- Dashboard 核准寫入失敗：維持待核准，可安全重試。
- 核准同步失敗：維持 D1 核准並顯示尚未同步，下一次重試。
- Dashboard 建置或部署失敗：不切換正式版本，保留上一個可用部署並顯示受阻。
- 日曆涵蓋不足：停止計算最新狀態並提示更新日曆。

## 測試與驗收

### 交易日規則

- 平日 07:30 前、07:30 後、週末、完整休市、提早收盤及跨年日曆測試。
- 週一正確指向前一個週五交易時段與週末事件。
- 缺少年度日曆時顯示受阻，不誤判為最新。

### 核准流程

- 待核准卡片顯示二次確認；取消不寫入。
- 未授權、跨來源、錯誤版本及非待核准成果不能核准。
- 重複提交只產生一筆事件。
- 核准後首頁、待核准中心、晨報全文與風險頁狀態一致。
- 新版本不繼承舊版本核准。
- 同步成功、同步重試、內容雜湊不符及尚未具備服務授權均有明確狀態。

### 晨報與發布

- 2026-07-31 晨報固定五則且來源、截止時間、反證及風險分類完整。
- 風險分數可由五項基準分與事件調整重現。
- 所有自動產生成果均為 `待核准`。
- Dashboard 型別、程式碼檢查、單元測試、畫面測試、正式建置及權限測試通過。
- 執行 `sh scripts/validation/validate-workspace.sh` 通過後才可宣稱完成。
- 私人部署維持既有擁有者限制，部署後確認首頁、資料狀態、核准中心、全文與風險頁。

## 決策與啟用紀錄

- 以 `records/decisions/` 記錄使用者於 2026-08-02 核准交易日規則、Dashboard 按鍵核准方案及每日排程。
- 自動排程只有在程式、研究模板、權限、部署及失敗回報都驗證完成後才啟用。
- 功能完成後將隔離工作分支整合回 `jj-ai-team` 主分支，避免排程對未包含新功能的主線執行。

## 非目標

- 不自動對外發布晨報或社群內容。
- 不自動執行投資、Beta、再平衡或持股調整。
- 不在第一版建立完整審稿留言系統或多人權限模型。
- 不把游庭皓或財經 M 平方列為第一版必要來源。
- 不改變已核准的市場風險計分方法；方法調整需另建版本與決策紀錄。
