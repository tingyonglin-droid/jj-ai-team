# Threads 成效改採累積數據

- 決策日期：2026-07-30
- 決策者：使用者
- 背景：固定 24／72 小時成效需要依發文時間準時擷取，歷史數據也無法回推，實作與維護成本較高。
- 選項：建立固定 24／72 小時快照；或沿用現有 Threads API 同步的累積成效。
- 決定：取消固定 24／72 小時快照、獨立快照 Database 與相關排程；以累積按讚數為主要成效指標，必要時輔以現有累積觸及、留言、轉發、引用與分享。
- 理由：降低系統與維護複雜度，符合目前分析需求。
- 適用範圍：Threads 成效同步、內容復盤與後續成效分析。
- 生效日：2026-07-30
- 後續檢查日：累積更多貼文後，若不同發布時間造成的比較偏差已影響決策，再重新評估。
- 分析限制：每次報告須標示發布時間與資料截止時間；不得將不同累積期間視為同等觀察窗，也不得回推或宣稱歷史 24／72 小時成效。
- 人工核准邊界：本決定不授權新增資料庫、排程或修改同步程式。
- 取代關係：取代 `records/decisions/2026-07-30-threads-knowledge-and-analysis-baseline.md` 中「規劃固定 24／72 小時觀察窗」的部分，其餘決定維持有效。
- 關聯文件：`records/reviews/2026-07-30-threads-tag-correction-and-snapshot-proposal.md`、`records/reviews/2026-07-30-threads-baseline-review.md`。
